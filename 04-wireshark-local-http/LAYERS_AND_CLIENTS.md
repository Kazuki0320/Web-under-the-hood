# LAYERS_AND_CLIENTS

## テーマ
TCPクライアントとHTTPクライアントの違いを、レイヤー（L3/L4/L7）で整理する。

## 結論
- TCPクライアント（例: `nc`）: 運ぶだけ。中身の意味は理解しない。
- HTTPクライアント（例: `curl`, ブラウザ）: HTTPルールを理解して会話する。

## レイヤー対応
- L7（Application）: HTTP
- L4（Transport）: TCP
- L3（Network）: IP

## 役割分担
- HTTP: 何をしたいか（`GET /hello` など）を表現
- TCP: 接続、順序保証、再送制御
- IP: 宛先への配送経路を決定

## 実験との対応
- 今回は `nc` でHTTP文字列を手入力して送る
- つまり「HTTPクライアントの仕事の一部」を手で再現している

## よくある誤解
- 誤解: HTTPが接続を作る
  - 正: 接続はTCPが作る
- 誤解: GET送信で即レスポンス
  - 正: その前に3-way handshakeが必要
- 誤解: 1リクエスト = 1パケット
  - 正: 複数パケットに分かれることがある

## 一言まとめ
HTTPは会話ルール、TCPは配送路。
