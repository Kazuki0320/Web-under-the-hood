# NginxとTomcatの違い

このドキュメントは、NginxとTomcatの技術的な違いと、画面表示までの処理フローの違いを整理したものです。

## 1. 一言でいう役割の違い

- Nginx
  - 主役: Webサーバー / リバースプロキシ
  - 得意: 静的ファイル配信、TLS終端、負荷分散、リバースプロキシ
- Tomcat
  - 主役: Java Servlet/JSP を実行するアプリケーションサーバー
  - 得意: Javaコードの実行、動的コンテンツ生成（HTML/JSONなど）

## 2. 画面表示までの何が違うか

### Nginx（静的配信）の流れ

1. リクエストを受信する。
2. `location` と `root` / `alias` で対象ファイルを解決する。
3. `index.html` や `style.css` などをそのまま返す。

ポイント:
- 既に存在するファイルを返すので高速。
- リクエストごとの複雑な業務ロジック実行はしない。

### Tomcat（Servlet/JSP）の流れ

1. リクエストを受信する。
2. `web.xml` やアノテーションでマッピングされたServletを決定する。
3. Javaコードを実行する（DB参照、条件分岐、セッション処理など）。
4. 必要ならJSPでHTMLを生成する。
5. 生成結果をレスポンスとして返す。

ポイント:
- リクエスト時に処理して内容を作る。
- ユーザーや状態に応じた動的表示に強い。

## 3. TomcatはSSRか？

- Tomcatそのものは「SSRという方式」ではなく「Java Webアプリを動かす実行基盤」。
- ただし、Tomcat上でJSP/Thymeleaf/ServletでHTMLを生成して返すなら、それはSSR（サーバーサイドレンダリング）。

## 4. SSRと静的ファイル配信の違い

### 静的ファイル配信

- 配信物は事前にある（`index.html` など）。
- サーバーは主にファイルを返すだけ。
- 速くて構成が単純。

### SSR

- リクエストごとにサーバーでHTMLを生成する。
- ユーザーごとに内容を変えやすい。
- 柔軟だが、サーバー負荷と実装複雑度は上がる。

## 5. 実運用での組み合わせ（よくある形）

Nginxを前段、Tomcatを後段に置く構成が一般的。

1. Nginxが外部リクエストを受ける。
2. 静的ファイルはNginxが直接返す。
3. 動的処理が必要なリクエストだけTomcatへ転送する。
4. TomcatがJava処理を実行してHTML/JSONを返す。

この構成の利点:
- Nginxで高速配信・TLS・中継を担当。
- Tomcatはアプリロジックに専念できる。

## 6. 例: 同じURLでも実装方式で役割が変わる

- `/` が `index.html` を返すなら静的配信（Nginx向き）。
- `/home` がServlet経由でJSP描画ならSSR（Tomcat向き）。

要点:
- 「事前にあるファイルを返す」のが静的配信。
- 「その場でHTMLを作って返す」のがSSR。

## 7. TLS終端（簡潔）

TLS終端は、HTTPS通信の暗号化を「入口のサーバー」で復号して、後段へ渡すこと。

- 典型: NginxでTLS終端し、TomcatへはHTTPで転送
- 利点: 証明書管理を入口に集約できる、後段アプリをシンプルに保てる
